# 迹波上下位机联调协议

本文供下位机固件开发使用。下位机周期上报采样数据，上位机据此显示波形和状态。需要控制设备时，上位机通过控制台发送命令，下位机负责解析、校验、执行和应答。

## 1. 选择通信方式

| 需求 | 上位机配置 | 下位机配合 |
| --- | --- | --- |
| 显示品质、转速、推杆行程和状态 | 传感数据接收 → 串口 | 周期发送 `FE` 扩展帧 |
| 显示品质和转速 | 传感数据接收 → 串口 | 周期发送 `FF` 旧帧 |
| 仅显示含杂率和破碎率 | 传感数据接收 → CAN 总线 | 周期发送 8 字节品质帧 |
| 发送控制命令 | 控制台配置 → UART 或 CAN | 接收命令并在同一控制通道回复 |

设备有 UART 和 CAN 时，可以用 **UART 上报 `FE` 帧、CAN 收发控制命令**。采集和控制都走 UART 时，上位机需要分别连接两个串口。品质采集和控制都走 CAN 时，可以共用一个 CAN 接口，采集、命令和应答使用不同 ID。若要通过 CAN 显示转速和推杆，还需定义对应报文并扩展上位机解析。

## 2. 下位机周期上报

上位机连接采集通道后即可接收数据。固件可以先按 **10 Hz（每 100 ms 一帧）** 联调，停机时也继续上报当前的有效数据。有效采样约 2 秒未更新时，上位机会提示数据过期。波形时间轴使用上位机接收时间，采集帧无需设备时间戳。

### 2.1 串口采集

两端串口参数保持一致。上位机默认 `115200` 波特率、8 数据位、无校验、1 停止位、无流控。所有浮点字段使用 **IEEE 754 `float32` 小端**。按下表偏移组包并发送原始字节，避免结构体对齐填充。每次采样选一种帧发送。采集帧无 CRC、无换行，日志若共用采集线，只能插在完整采集帧之间。

| 字节偏移（从 0 开始） | `FF` 旧帧，18 字节 | `FE` 扩展帧，23 字节 |
| --- | --- | --- |
| 0 | 帧头 `0xFF` | 帧头 `0xFE` |
| 1～4 | 破碎率，比例 `0～1` | 破碎率，比例 `0～1` |
| 5～8 | 含杂率，比例 `0～1` | 含杂率，比例 `0～1` |
| 9～12 | 实际电机转速，rpm | 实际电机转速，rpm |
| 13～16 | 目标电机转速，rpm | 目标电机转速，rpm |
| 17～20 | 偏移 17 为帧尾 `0xEE`，帧到此结束 | 推杆行程，`float32` |
| 21 | — | 推杆状态码，`uint8` |
| 22 | — | 帧尾 `0xEE` |

- 破碎率 2% 发 `0.02`，含杂率 3% 发 `0.03`。推杆行程 42.5% 发 `42.5`，有效范围 `0～100`，其中 `0` 为完全缩回，`100` 为完全伸出。
- 电机实际转速为 `0` 时显示停止，非零时显示运行。推杆状态由固件直接上报。使用 `FF` 旧帧时，推杆显示暂无数据。
- 浮点字段必须是有限数，推杆行程和状态码必须在有效范围内。

| 推杆状态码 | 含义 |
| --- | --- |
| `0` | 未知 |
| `1` | 停止 |
| `2` | 伸出中 |
| `3` | 缩回中 |
| `4` | 完全缩回 |
| `5` | 完全伸出 |
| `6` | 故障 |

以下报文应显示破碎率 2%、含杂率 3%、实际转速 140 rpm、目标转速 150 rpm、推杆行程 42.5%、状态为伸出中。

```text
FE 0A D7 A3 3C 8F C2 F5 3C 00 00 0C 43 00 00 16 43 00 00 2A 42 02 EE
```

### 2.2 CAN 采集

使用经典 CAN 的 **11 位标准数据帧，DLC 固定为 8**。总线波特率保持一致，默认采集 ID 为 `0x123`。上位机采集栏直接填 `0x123`，因为该栏的 `123` 会按十进制读取。

| CAN 数据区（从 0 开始） | 内容 |
| --- | --- |
| 0～3 | 含杂率，`float32` 小端，比例 `0～1` |
| 4～7 | 破碎率，`float32` 小端，比例 `0～1` |

**CAN 先含杂率、后破碎率，串口先破碎率、后含杂率。** 含杂率 3%、破碎率 2% 的测试报文为 `123#8FC2F53C0AD7A33C`，`#` 后是数据区。这一帧只承载两项品质数据，转速和推杆在 CAN 采集模式下显示缺失。

## 3. 下位机接收控制台命令

上位机提供 UART 文本、UART HEX 和 CAN 命令发送。**命令名、命令号、参数类型、合法范围以及应答格式由固件定义**。以下用“设置目标转速为 150 rpm”举例。已有固件命令表时，直接按其定义填写控制台。

### 3.1 UART 文本命令

1. 上位机在控制台选 UART 文本模式，输入 `SET_RPM 150`，结尾选 `LF`。发送的内容为 `SET_RPM 150\n`。
2. 下位机逐字节缓存，收到 `LF` 后取出整行，解析命令和参数，检查转速范围，再更新目标转速。若约定用 `CRLF`，解析时去掉行末 `CR`。上位机也支持 `CR` 和无结尾，双方按同一规则配置。
3. 下位机从控制串口回复，例如成功时发 `OK SET_RPM 150\r\n`，失败时发 `ERR RANGE\r\n`。控制台接收显示选文本即可查看。

如果固件已经提供交互式 Shell，也可以用上位机的“UART 终端”逐键输入。终端回车默认发 `CR`，可改成 `LF` 或 `CRLF`。

### 3.2 UART HEX 命令

- 上位机输入完整命令帧，例如 `AA 55 01`，发出的就是对应的原始字节，HEX 模式不会追加换行。帧头、长度、校验和等字段由固件协议定义，需要的字节全部填进控制台。
- 下位机按协议缓存和组帧，处理分包、粘包。收齐一帧后检查长度、命令号、参数和协议要求的校验字段，再执行并回复。控制台接收显示可切为 HEX 查看二进制应答。

### 3.3 CAN 命令

上位机发经典 CAN 11 位标准数据帧。发送 ID 按十六进制填写，首次默认 `401`，即 `0x401`。数据区字节 0 是命令号，字节 1～7 是可选参数，所以 DLC 为 `1～8`。

下面是一套可直接用于联调的示例约定。

| 方向 | CAN 报文 | 解析规则 |
| --- | --- | --- |
| 上位机 → 下位机 | `401#019600` | 标准帧 `0x401`，DLC 3。`01` 为设置目标转速，`96 00` 是小端 `uint16`，数值为 150 rpm。 |
| 下位机 → 上位机 | `402#0100` | 标准帧 `0x402`，DLC 2。`01` 回显命令号，`00` 表示目标值已成功更新。 |

上位机发送栏填 **发送 ID `401`、命令号 `0x01`、参数 `96 00`**。控制台 CAN 接收 ID 填 `402`。下位机按标准帧 ID 接收命令，检查命令号、DLC 和参数范围，通过后更新目标值并回复。参数错误时可以约定回复 `402#0101`，末字节 `01` 表示参数错误。

## 4. 联调验收

1. 在上位机“传感数据接收”中连接采集通道，让下位机周期发送对应测试报文，核对波形单位和状态显示。
2. 在“控制台配置”中连接控制通道，用与固件约定一致的命令修改目标值，检查控制台能否收到成功或失败应答。
3. 通过串口采集转速时，检查后续采集帧里的目标转速是否更新，实际转速是否持续按实测值上报。上位机的“已排队”表示命令已交给发送端。设备是否应用命令看下位机应答，电机是否达到目标看实际转速波形。
